## 5. 安全与节能增强：明确设计，不冒充已确认故障

### #18 备份与 LAN 共享

推荐先在导出/共享开启入口清楚提示实际风险；若纳入完整加固：

- 备份使用密码派生密钥与带认证的加密封装（标准库 PBKDF2-HMAC-SHA256 + AES-GCM，随机盐与 nonce，格式版本明确）；不使用只能在原设备解密的 Keystore 密钥作为唯一可移植备份密钥。
- 默认导出加密；明文兼容导出需显式选择。旧 Links/AnyBox 备份继续可导入；旧文件保留，不自动覆盖为新格式。
- 错误密码、篡改/截断、超大输入必须在数据库替换之前失败；仍沿用现有恢复事务与运行配置回滚。使用合成凭据验证离线文件中不可直接读出秘密、跨安装恢复、WebDAV 上传/下载；密码不进日志/普通文档。
- LAN 认证复用 mixed 入站现有 users 能力，覆盖 allowLan 的 mixed-in 与 share-in；不硬编码默认密码。默认仍关闭 LAN；开启时必须明确选择受认证共享或接受无认证模式的风险。既有共享配置不能悄悄失效或重设密码。
- 验收：默认无 LAN 暴露；无/错凭据拒绝、正确凭据成功；HTTP/SOCKS使用路径、关闭后监听撤除、本机现有使用不回归。仅在隔离模拟器/本机受控连接测试，不访问第三方设备。

### #19 明文网络边界

- 保留任意用户 HTTP 订阅、本地 API 和内网 WebDAV 的明确兼容需求。没有域名清单时，不用静态 XML 白名单假装覆盖动态 URL。
- 在导入/设置确认中显示 HTTP 凭据与明文内容风险；检查 HTTPS→HTTP 重定向、跨源认证头转发是否满足既有安全约束，若发现明确缺陷再定向修复。
- 若用户选择“严格禁止公网 HTTP”的额外政策，需在业务 URL 入口实施并明确旧配置迁移；不能静默打断旧订阅。
- Android network security policy 是尽力而为的 Java/平台策略，不能替代原生 socket/Go 的策略。[官方 usesCleartextTraffic 说明](https://developer.android.com/guide/topics/manifest/application-element#usesCleartextTraffic)

### #34 WireGuard 与自动测速休眠

- 仅在希望完成该历史增强时实施。目标是 Doze 时暂停可选自动测速，而非让整套 WireGuard 隧道 sleep；手动测试、订阅更新的临时唤醒需定义并恢复原状态。
